# Domain Models

This document describes current trainer-web domain models in mobile-oriented language. Source-of-truth types often live in server-only files; mobile should copy or re-declare safe DTO shapes, not import server-only modules directly.

## User

Current source:

- `src/lib/supabase/lkUsers.ts`.
- `src/lib/auth/lkAccess.ts`.

Fields observed through access resolution:

- `email`: normalized lower-case email.
- `role`: `admin`, `coach`, or `client`.
- `lkEnabled`: boolean access flag.

Server-owned:

- Role.
- LK enabled/disabled state.

Mobile editable:

- None in current code.

Never generated by mobile:

- Role.
- Access flags.

## Coach

Current source:

- `src/lib/supabase/coachStudents.ts`.
- `getCoachByEmail(...)` returns `CoachProfileRow`.

Fields:

- `id`: coach UUID.
- `email`: coach email.
- `access_level`: `coach` or `head_coach`.
- `is_active`: boolean.

Server-owned:

- `id`, access level, active state.

Mobile note:

- Student app may show coach name/contact later, but current student client profile does not expose coach details.

## Student / Client

Current sources:

- `src/lib/supabase/lkClients.ts`.
- `src/lib/supabase/coachStudents.ts`.
- `src/lib/airtable/coachStudents.ts` shared `CoachStudent` type.

Fields currently exposed in LK profile:

- `email`.
- `balance`.
- `finalDay`.
- `lkEnabled`.

Admin/coach table fields:

- `id`, `name`, `email`, `finalDay`, `balance`, `nextWorkoutAt`.
- Admin-only display fields: `grPrice`, `dsPrice`, `prPrice`, `spPrice`, `futurePlan`, `firstFact`, `tag`.

Server-owned:

- `id`, email identity, balance, final access date, pricing fields, active state.

Mobile editable:

- None currently implemented.

Relationships:

- Coach/client relation is checked through `coach_clients` in `src/lib/supabase/coachWorkouts.ts`.

## Workout

Current source:

- `CoachWorkout` in `src/lib/supabase/coachWorkouts.ts`.

Fields:

- `id`: server workout UUID.
- `clientId`: student/client UUID.
- `date`: `YYYY-MM-DD`.
- `title`: string.
- `exercises`: `CoachWorkoutExercise[]`.
- `groups`: optional `CoachWorkoutExerciseGroup[]`.
- `coachComment`: optional string.
- `updatedAt`: optional server timestamp.

Server-owned:

- `id`, `clientId`, `updatedAt`.

Client-editable in trainer web:

- `date`, `title`, `coachComment`, exercises, groups, metrics.

Student mobile editable:

- Not currently defined. Future completion/feedback should use student-specific fields/endpoints, not coach mutation endpoints.

Optimistic behavior:

- `src/components/lk/LkStudentCalendar.tsx` may temporarily create IDs prefixed with `optimistic-` for pasted UI cards.
- `optimistic-*` IDs are temporary UI identifiers only.
- `optimistic-*` IDs must never be sent to persisted update/delete/move endpoints requiring UUIDs.

## WorkoutExercise

Current source:

- `CoachWorkoutExercise` in `src/lib/supabase/coachWorkouts.ts`.

Fields:

- `id`: optional server exercise row UUID.
- `exerciseId`: optional reference to exercise library UUID.
- `groupId`: optional group/combo UUID.
- `title`: display title.
- `details`: optional derived text.
- `sets`, `reps`, `rest`, `tempo`, `notes`: optional raw strings.
- `sortOrder`: optional number.

Server-owned:

- Persisted `id`.
- Persisted group membership IDs.

Client-editable in trainer web:

- Title, exercise library selection, group membership, metrics, notes, sort order.

Mobile note:

- Student app should display raw strings exactly unless a future normalized metric schema is introduced.

## ExerciseLibraryItem

Current source:

- `src/lib/supabase/exerciseLibrary.ts`.

Fields:

- `id`: exercise UUID.
- `title`.
- `videoProvider`: currently Cloudflare for newly uploaded exercises.
- `videoAssetId`.
- `videoUrl`.
- `watchUrl`: web route, e.g. `/lk/exercises/{id}/video`.
- `thumbnailUrl`.
- `description`.
- `tags`.
- `isActive`.
- `createdByCoachId`.
- `ownerType`.
- `canEdit`.
- `canArchive`.
- `createdAt`, `updatedAt`.

Server-owned:

- IDs, video asset IDs, permissions, ownership, timestamps.

Mobile editable:

- None for student MVP.

Mobile note:

- `watchUrl` is web-only. Mobile should use a student-safe video playback field or endpoint.

## ExerciseGroup / Combo

Current sources:

- `CoachWorkoutExerciseGroup` in `src/lib/supabase/coachWorkouts.ts`.
- `ProgramTemplateExerciseGroup` in `src/lib/supabase/programTemplates.ts`.

Fields:

- `id`: group UUID.
- `title`: default often "Комбо".
- `sets`, `rest`, `notes`: optional raw strings.
- `sortOrder`: number.
- `exercises`: grouped exercise list when read from server.

Client-editable in trainer web:

- Title, metrics, notes, grouping/ungrouping, order.

Mobile note:

- Student app should render combos as grouped blocks. It should not generate persisted group IDs.

## WorkoutMetric

Current representation:

- Raw string fields: `sets`, `reps`, `rest`, `tempo`, `notes`.
- There is no normalized metric schema.

Important behavior:

- Reps text is intentionally raw and should not be normalized or rewritten.
- Rest text can be display-only until timer parsing rules are defined.

Mobile note:

- Use display strings as prescribed.
- If rest timer is added, define parser rules and fallback behavior.

## WorkoutCompletion and ExerciseCompletion

Current status:

- No dedicated student workout completion or exercise completion model found in LK code.
- Calendar status exists at database row level (`status` selected in `coachWorkouts.ts`) but it is not exposed in `CoachWorkout`.

Required before mobile:

- Define completion model, ownership, timestamps, conflict rules, and endpoints.

## Program

Current source:

- `ProgramTemplate` in `src/lib/supabase/programTemplates.ts`.

Fields:

- `id`, `coachId`, `isGlobal`, `title`, `description`.
- `durationDays`, `weeksCount`, `level`, `goal`, `tags`.
- `isActive`, `ownerType`, `canEdit`, `canArchive`.
- `createdAt`, `updatedAt`, `workoutsCount`, `workouts`.

Server-owned:

Student mobile note:

- Programs are currently a trainer library concept. Student app likely needs assigned calendar workouts, not direct program editing.

## ProgressMetric

Current status:

Required before mobile:

## Comment / Feedback

Current fields:

- `coachComment` on workouts.
- `notes` on exercises/groups.
- Support chat endpoint exists at `src/app/api/support-chat/route.ts`, but it is not a coach-student feedback system.

Missing for mobile:

- Student workout feedback entity.
- Coach response entity.
- Notification/read-state model.

## Fields Mobile Must Never Generate

- Persisted UUIDs for workouts, exercises, groups, users, coaches, clients.
- `createdAt`, `updatedAt`, `expectedUpdatedAt` values except echoing server-provided concurrency tokens.
- Role/access fields.
- Ownership/permission fields such as `canEdit`, `canArchive`, `ownerType`.
- Cloudflare Stream credentials or trusted video verification state.
- Database IDs for copied source workouts/groups/exercises.

## Optimistic ID Rule

Temporary client IDs may be useful for rendering pending state, but use a clearly non-UUID prefix such as `optimistic-`. These IDs must be reconciled with authoritative server data before any persisted update/delete/move request. Never strip the prefix and never generate fake UUIDs.
